## 1. Why This Note Exists

The first few units of the working manuscript have already been manually edited by the user. They are useful as a style signal, but they are not a reliable baseline for the rest of the book. A repair plan or implementation that only follows Units 1-4 will miss later-book problems in routine email units, internal-document units, editing units, capstone units, and module review workshops.

This note records a representative sample from across the manuscript so future repair work starts from the whole book, not from the opening units alone.

## 3. Cross-Book Findings That Are Not Visible From The Opening Units Alone

### 3.1 Later units have different structural failures

The opening units mainly show duplicate visible `F` / `H` sections and manually altered instruction style. Later units add different problems:

- Module 6 units contain many `#### A-H` headings that function like lost top-level activities.
- Unit 23 has a visibly non-teachable order, with `F` appearing before `E` and `D`.
- Units 8-18 often add extra `A` or `E` sections for primers, planning boards, or extended writing tasks.
- Review workshops do not follow the same unit shell at all and need their own review-workshop standard.

Implementation consequence: do not create one opening-unit template and apply it blindly to the full book.

### 3.2 Module review workshops need their own repair pass

Module review workshops include valuable cumulative practice, but their current presentation often has:

- lowercase headings such as `module 2 email control checklist` and `module 6 final self-edit routine`
- stacked titles where the `###` heading and the div title repeat each other
- multi-part writing tasks where labels and placeholder row counts need checking against actual output length
- useful reflection questions that may be better integrated with the task rather than appearing as a separate mini-list after a long prompt

Implementation consequence: treat module workshops as a separate seventh family after Units 1-23, not as ordinary units and not as optional back matter.

### 3.3 Capstone units cannot be repaired by opening-unit rules

Units 19-23 use integrated two-document and three-document tasks. Their key repair needs are different from early sentence or email units:

- document-role labels must be preserved and made more explicit, not removed as generic clutter
- paired and multi-document response boxes should stay visibly separated
- `####` headings need normalization without flattening the learner's document sequence
- prompts must distinguish external message, internal explanation, notice, revision note, and portfolio item

Implementation consequence: capstone units need a document-pack standard before prose-level cleanup.

### 3.4 Editing units require special handling of arrows and transformation prompts

Unit 16 and neighboring editing units use transformation notation such as before/after arrows, correction lists, and short rewrite prompts. These are easy to damage if all arrows or short lines are treated as formatting errors.

Implementation consequence: replace unclear `->` notation with readable prose or a consistent arrow style, but preserve the before/after pedagogical relationship.

### 3.5 Placeholder calibration must be checked after activity repair

The cross-book sample confirms that placeholder sizing cannot be solved from the first units alone. Later tasks include:

- sentence-level corrections
- paragraph rewrites
- two-email outputs
- internal/external paired documents
- final portfolio components
- module review transfer packs

Implementation consequence: placeholder types and `rows=N` values should be verified after each unit or workshop's task instructions are stable, then checked again in a whole-book pass.

## 4. Implementation Guardrails Added By This Reading

1. Do not use Units 1-4 as the diagnostic baseline.
2. Use Unit 1 only as a pilot to test the repair workflow.
3. Before applying a reusable pattern, compare it against at least one later unit from each major activity family.
4. Repair module review workshops explicitly; do not leave them for generic proofreading.
5. Treat Module 6 as a capstone document-pack problem, not as a simple A-H heading cleanup.
6. Preserve pedagogically meaningful labels in paired or multi-document tasks, even while removing redundant `Write Here` labels elsewhere.
7. Delay final placeholder sizing until after instruction and activity-boundary repair.
8. Check student-facing wording for intermediate-level readability in every unit family, especially later modules where instructions become more abstract.
